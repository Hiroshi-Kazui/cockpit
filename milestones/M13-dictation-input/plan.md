# M13 — ペイン下部の口述入力欄

## 1. 背景・要望

> Aqua Voiceによる音声入力ができないので、できるようにしたい。

> 最後の文字起こしを張り付けはできますが、1+3だけではだめでした。最後の文字起こしを張り付けは
> いささか面倒です。

（2026-08-26 セッションでのユーザー発言。Aqua Voice の設定変更—「常にインスタント」化・送信コマンドの
変更—では解決せず、Aqua の「最後の文字起こしを貼り付け」ホットキーを毎回押す運用は不可という判断）

同セッションでの実測（ユーザー操作による確認）:

- Aqua の自動挿入 → ペイン（xterm.js の隠し textarea）: **入らない**
- Aqua の「最後の文字起こしを貼り付け」→ ペイン: **入る**（xterm の paste 経路は機能している）
- 口述後に手で Ctrl+V → ペイン: **入らない**（T1 NG。クリップボード監視案は前提が崩れて破棄）
- Aqua の自動挿入 → 目的入力ダイアログの `<textarea>`: **入る**（T2 OK）

外部報告: claude-code issue #51725 / #38620 / #39983 / #53451（Windows で擬似キーストローク入力が
claude の TUI に届かない）。上流未修正。

したがって「普通の HTML 入力欄を cockpit 側に用意し、そこから pty へ送る」のが唯一実測に裏付けられた
経路。UI 形態（常設欄 / ホットキーで開くオーバーレイ）と Enter の挙動はユーザーが選択済み:
**ペイン下部に常設の入力欄**、**Enter で送信**（2026-08-26）。

## 2. 要件

- **R-1（常設の入力欄）**: 各ペインの端末の下に、常に存在する定数高の入力欄を置く。pty の起動状態・
  レイアウト（1/2分割/4分割）・情報行の有無に関わらず高さが変わらない。内容が増えても欄は伸びず内部で
  スクロールする（ADR-0015 D-3）
- **R-2（端末をリサイズしない）**: 欄の追加・内容変更によって、実行中の pty の cols/rows が変化しない。
  `pty.resize` が欄起因で呼ばれる経路が存在しない（1a78edb / ADR-0014 で根絶した崩れの再導入禁止）
- **R-3（送信）**: Enter で、1行化したテキストを `Terminal.paste()` に渡し、続けて `Terminal.input('\r')`
  を送る。バイト列は既存の `term.onData → pty.write` を通り、**新規 IPC チャネルは追加しない**
  （ADR-0015 D-1）
- **R-4（改行の扱い）**: 送信前に `normalizeInitialPromptText`（`src/shared/prompt.ts`）で内部改行を
  空白へ潰す（ADR-0015 D-2）。Shift+Enter は欄内の改行で、送信はしない
- **R-5（キー割り当て）**: Enter=送信 / Shift+Enter=欄内改行 / Ctrl+Enter=挿入のみ（CR を送らない）/
  Escape=そのペインの端末へフォーカスを戻す。**IME 変換中（`isComposing`）の Enter では送信しない**。
  既存の `Ctrl+1..4`（M5 のペイン間フォーカス移動）の挙動は変更しない
- **R-6（送信後の状態）**: 送信に成功したら欄を空にし、フォーカスは欄に残す（続けて口述できる）。
  空文字・空白のみでは何も送らない（`paste` も `input` も呼ばない）
- **R-7（送信先の限定）**: ペイン `n` の欄はペイン `n` の pty にのみ送る。pty 未起動（`running === false`）
  の間は欄を `disabled` にし、理由が分かるプレースホルダを出す（ADR-0015 D-4/D-5）
- **R-8（素通し原則の維持）**: xterm.js の入力経路（keydown / composition / paste / `input` イベント）と
  pty 出力の扱いに変更を加えない。spec §4.1 は不変（ADR-0015 D-7）
- **R-9（アクセシビリティ）**: 欄に `aria-label` を与え、操作方法（Enter で送信）が視覚・支援技術の
  双方から分かる。マウスなしで到達できる

## 3. 設計判断の要旨（本文は ADR-0015）

- 挿入は `Terminal.paste()` へ委譲。bracketed paste の可否判定を cockpit で二重実装しない（D-1）
- 送信前に改行を空白へ潰す。`purposeCoordinator` の初回プロンプトと同じ規則に揃える（D-2）
- 欄は常設・定数高。条件付きレンダリングは実行中リサイズを再導入するため禁止（D-3）
- ペインごとに持ち、そのペインにだけ送る。「アクティブペイン」概念を作らない（D-4）
- pty 未起動時は `disabled`。テキストを受け取って捨てない（D-5）

## 4. 実装フェーズ

1. **純関数（test-first: red 確認 → green）** — 送信可否とペイロードの決定を純関数へ切り出す
   （例 `src/shared/dictation.ts`: 入力テキスト＋修飾キーの組から
   `{ kind: 'none' | 'insert' | 'submit'; text: string }` を返す）。改行の潰し・空文字の判定・
   Ctrl+Enter と Enter の差はここで固定し、コンポーネントには残さない
2. **usePtyPane の拡張（unit）** — `sendText(text, submit)` を返す。内部で `term.paste()` と
   `term.input('\r')` を呼ぶだけで、IPC を直接叩かない。`running === false` では何もしない
3. **renderer（Pane / styles）** — 端末の下に定数高の入力欄を追加。キー処理は R-5 のとおり。
   `.pane-info` と同じ「常に存在する定数高の帯」の作りに揃える
4. **E2E** — `e2e/app.spec.ts`（または新規 `e2e/dictation.spec.ts`）で、欄に文字を入れて Enter →
   fake-claude が1行として受け取り、アーカイブされた transcript にその文言が現れることを検証
   （既存 `app.spec.ts:173-210` の「端末に直接 type して transcript を確認する」手順の対応物）。
   レイアウト切替を挟んでも欄が消えないこと、pty 未起動時に `disabled` であることも固定する
5. **回帰** — `terminal-repaint.spec.ts` 4本（欄の追加で行数の不変条件が壊れていないこと）と
   既存 E2E / unit 全走

## 5. リスク

- **欄の高さが端末の行数に効く**: 欄はマウント時から常設なので実行中のリサイズは起きないが、
  実装を誤って条件付きレンダリングにすると M12 で根絶した崩れが戻る。R-2 を E2E
  （`terminal-repaint.spec.ts`）で守る
- **bracketed paste が無効なときの多行貼り付け**: D-2 の1行化で回避するが、1行化は
  「口述した通りの改行が残らない」という UX 上の副作用でもある。許容し、必要なら別マイルストーン
- **claude 側の TUI が paste をどう解釈するか**は cockpit の制御外。Aqua の貼り付けホットキーで
  実際に入ることは実測済みだが、将来の claude 更新で変わり得る（spec §8 相当のリスク）
- **口述欄と端末のフォーカス往復**: Escape の割り当てが Aqua のキャンセルキー（Escape）と重なる。
  Aqua が録音中に Escape を消費する場合、欄からのフォーカス復帰が効かないことがある（実害は小）

## 6. スコープ外

- 改行を潰さずに複数行のまま claude へ渡す経路
- xterm.js の入力受け口の改造（隠し textarea の `input` イベント監視など）
- クリップボード監視による自動挿入（T1 NG で前提が崩れた）
- cockpit 自前の音声認識（マイク → Whisper 等）
- Aqua Voice 側の設定変更で解決する試み（実測済みで不足と判明）
- 入力履歴（↑キーでの呼び戻し）、ホットキーで欄へフォーカスを飛ばす機能
- 目的入力ダイアログ（`PurposeDialog`）の既存キー割り当ての変更
