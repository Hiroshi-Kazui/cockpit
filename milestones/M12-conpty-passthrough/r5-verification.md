# M12 R-5 実機確認の記録（2026-08-11）

実 claude CLI（Claude Code v2.1.227）を cockpit のペインで起動し、スクロール・ウィンドウリサイズ・
分割線ドラッグを実行して、報告された「左端の文字が1文字分左にずれ、行頭に前の行の文字が残る」崩れが
再現するかを検証した。**fake-claude は使用していない。**

## 手順

一時スペック `e2e/r5-real-claude.spec.ts`（検証後に削除）で自動化した。

1. 実アプリを起動し、ペイン0 の cwd を `C:\develop\cockpit`（claude が既に信頼済み）に設定
2. 「＋ 新規セッション」で実 claude を起動。TD-1 の目的プロンプト送信が完了するまで待機
   （完了判定は `✻ .+ for \d+s`。フッターの動詞は実行ごとに変わる）
3. claude の bash モード（`!cat <file>`）で素材40行を claude 自身の TUI に出力させる。
   素材は1行ごとに一意な行頭マーカーを持つ CJK 混在テキスト:
   `R5-NN|日本語テキスト→検証・確認（テスト）／① ああああああああ END`
   （全角 CJK ＋ East Asian Ambiguous 記号 `→ ・ （） ／ ①` の混在＝報告された文字種）
4. PageUp ×6 ＋ マウスホイール上 ×10（claude 自身のスクロールバックビューアが開く。
   "Jump to bottom (ctrl+End)" オーバーレイの出現で確認）→ ホイール下 ×10 ＋ PageDown ×8 で復帰
5. 実行中にウィンドウを −120×+80px、続けて +120×−80px リサイズ
6. 2分割レイアウトへ切替え、分割線を連続ドラッグ（−80 → −160 → −60 → +40 → +120px）
7. 各フェーズで xterm.js バッファを `__cockpitTestHooks.readPaneText` から読み出して判定

## 判定基準

行頭の空白と claude 自身のツール結果プレフィックス `⎿ ` を除去したうえで、
各行が `R5-NN` で始まり、ペイロード全体（`|日本語…END`）に byte 一致することを要求。
- **行頭に別行のセルが残る** → マーカーの前に空白以外が入るので検出される
- **1文字分左にずれる** → ペイロードが byte 一致しなくなるので検出される

claude の TUI 装飾（`⎿` プレフィックス、右寄せの "Jump to bottom" オーバーレイ）は
実 CLI が自分の UI を描いているものなので崩れとして扱わない（初回実行でこの2件を誤検出したため、
判定を実態に合わせて厳密化した）。

## 結果

| 条件 | intact マーカー | offenders | 判定 |
|---|---|---|---|
| 同梱 ConPTY（M12 既定） | **40/40** | **0** | PASS |
| 同梱 ConPTY（recorder 有効で再実行） | **40/40** | **0** | PASS |
| **旧 OS ConPTY（`COCKPIT_DISABLE_CONPTY_DLL=1`、対照）** | **40/40** | **0** | PASS |

端末ジオメトリは 193×44 で開始し、分割線ドラッグ後 112×44。

`COCKPIT_PTY_LOG_DIR` の recorder ログ（239 行 / 277KB、scratchpad に保管）が、
**実行中の pty に対して 44 回の resize が実際に発生した**ことを裏付けている:
`193×44 → 176×49 → 193×44 →`（ウィンドウリサイズ）`→ 95×44 → … → 72×43 → … → 112×44`
（分割線ドラッグの連続 resize）。崩れが起きうる条件を実際に踏んだうえで 0 件だった。

## 結論と限界（重要）

- **R-5 の要求（崩れが再現しないこと）は満たされた。** 実 claude・実 ConPTY・実スクロール・
  実行中リサイズ44回で、左ずれ・行頭残りは 0 件。
- **ただし対照条件（旧 OS ConPTY）でも 0 件だった。** つまり本検証は
  「M12 が崩れを直した」ことの証明にはなっていない。旧バックエンド側にも既に
  cec54ae（`convertEol` 除去）と 1a78edb（情報行の定数高化）が入っているため、
  報告された崩れは **M12 以前に既に解消していた可能性がある**（未確認）。
## 視覚確認（スクリーンショット）

`test-results/r5-real-claude.png`（2分割へ切替え・分割線ドラッグ後、実 claude セッション実行中に撮影）。
バッファ判定では見えない描画層を実物で確認した:

- 表示中の R5-07〜R5-39 の33行が**同一カラムで完全に左揃え**。1文字分ずれた行は無い
- 行頭に前の行のセルが残っている行は無い
- East Asian Ambiguous 記号（`→ ・ （） ／ ①`）が全行で同じ桁位置に揃っており、
  **xterm.js（Unicode 6 幅テーブル）と ConPTY の幅判定不一致による累積ドリフトも観測されない**
  （この経路は本検証の前に懸念として挙げていたもの。同梱 ConPTY 上では顕在化しなかった）

## 限界

1. 単一ジオメトリ（193×44 起点、ドラッグ後 112×44）でのみ実施
2. 崩れを意図的に再現する**陽性対照が無い**ため、判定ロジック自体が崩れを検出できることは未検証
3. 視覚確認は1枚の静止画であり、スクロール中の一過性の崩れは静止画では捉えられない
   （バッファ判定はスクロール中フェーズも対象にしており、そちらでは 0 件）
