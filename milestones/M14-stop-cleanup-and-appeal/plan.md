# M14 — 停止時クリーンナップ と 評価への異議申し立て

## 1. 背景・要望

> 完了後に停止を押した場合、画面をクリーンナップする。
> 評価がユーザの体感と一致しなかった場合、異議申し立てを行ったうえで再評価を求めることができるように

（2026-08-27 セッションでのユーザー発言。クリーンナップ範囲は「端末＋情報行」をユーザーが選択）

現状:

- 「完了」→「停止」の後もペインには前セッションの端末出力・`[claude exited: code=N]`・
  session telemetry 行・git 同期通知が残り、次の「＋ 新規セッション」まで居座る。
- `EvaluationDialog` の「再評価する」は同じ入力・同じプロンプトをもう一度回すだけで、
  ユーザーの体感とのズレを LLM に伝える経路が無い（`EvaluationRerunRequest` は `purposeId` のみ）。

## 2. 要件

- **R-1（完了後の停止でクリーンナップ）**: 目的が `completed` の状態で「停止」を押したとき、その
  ペインの端末バッファ（スクロールバック含む）を消し、情報行（session telemetry・git 同期通知・
  エラー行・アーカイブ警告）をリセットする。ヘッダの「完了済み」バッジと「評価を見る」は残す
- **R-2（進行中の目的では消さない）**: 目的が `active`（＝「再開」待ち）のままの停止では、従来どおり
  端末も情報行も一切消さない。`--continue` で戻る前の文脈を失わせない
- **R-3（停止後の残り物も残さない）**: kill 後に非同期で届く pty 出力と `[claude exited: code=N]` の
  通知行が、クリーンナップ後の画面に書き戻らない
- **R-4（端末をリサイズしない）**: クリーンナップ経路から `pty.resize` / `fitAddon.fit()` を呼ばない
  （ADR-0014 / M12 で根絶した表示崩れの再導入禁止）
- **R-5（異議申し立て）**: 評価ダイアログから、評価が体感と合わない理由を自由文で書いて再評価を
  要求できる。空文字・空白のみでは申し立て再評価を実行しない（従来の素の「再評価」は残す）
- **R-6（申し立てをプロンプトへ）**: 異議文は、異議の対象になった直前の評価のスコアと総評とともに
  評価プロンプトへ埋め込む。プロンプトは「申し立てに無条件で迎合せず、抜粋の実データと突き合わせ、
  支持できない部分は判断を維持してその旨を総評に書く」ことを明示する
- **R-7（記録の append-only 維持）**: 異議つき再評価も新しい `evaluations` 行を作る。既存行のスコア・
  異議文を書き換える経路を作らない。異議文は行に保存し、ダイアログと評価レポートに表示する

## 3. 設計判断の要旨（本文は ADR-0016）

- D-1: クリーンナップは「完了済み目的での停止」限定。D-2: 端末クリアは `Terminal.reset()`。
- D-3: 停止後の残余出力/exit 通知はフック内のフラグで抑止し、次の起動で解除。
- D-4: 異議文は `evaluations.appeal_text`（additive な `ALTER TABLE ... ADD COLUMN` 移行）。
- D-5: 異議文・直前評価の埋め込みは stdin のみ（TD-5 の injection 不変条件を継承）。

## 4. スコープ外

- 異議の履歴 UI（1 目的の異議つき再評価の一覧表示）。現行どおり「最新行が現行評価」のまま。
- 評価ダッシュボード（週次/月次集計）の表示変更。
