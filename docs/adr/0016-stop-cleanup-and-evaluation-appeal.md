# ADR-0016: 完了済み目的の停止時クリーンナップ と 評価への異議申し立て

- Status: accepted
- Date: 2026-08-27
- Milestone: M14（`milestones/M14-stop-cleanup-and-appeal/`）

## 文脈

「完了」→「停止」の後もペインに前セッションの端末出力と情報行が残る。また評価の再実行は同じ入力を
もう一度回すだけで、「評価が体感と違う」というユーザーの観測を評価器へ渡す経路が無い。

## 決定

**D-1: クリーンナップは「完了済み目的での停止」に限定する。**
`active` な目的の停止は `--continue` での再開待ちであり、端末に残った文脈はユーザーが再開判断に使う。
消してよいのは、目的が完了して次のセッションへ進む場合だけ。

**D-2: 端末クリアは `Terminal.reset()` 一発で行う。**
`clear()` はスクロールバックを残す。ペインを次のセッションのために空にするのが目的なので、
バッファ・スクロールバック・端末モードをまとめて初期化する `reset()` を使う。行数は変えないため
ConPTY 側の行認識とはずれない（ADR-0014 の不変条件を維持）。

**D-3: 停止直後の残余出力と exit 通知は、`usePtyPane` 内のフラグと「書き込みキューの排出待ち」の
二段で抑止する。** 残り物は 2 種類あり、フラグだけでは片方しか止まらない。

1. *まだ届いていない* 分: `pty.kill` の解決と `pty:exit`/`pty:data` の到達は非同期で前後し、
   `PtyManager.kill()` は殺したプロセス自身の残り `onData`/`onExit` を意図的に転送し続ける
   （generation guard のコメント参照）。クリーンナップ時に立てたフラグが立っている間は `pty:data` の
   書き込みと `[claude exited: ...]` の出力を行わない。フラグは次の `start` で下ろす。
2. *もう届いたが、まだ描かれていない* 分: xterm.js の `write()` は同期解析ではなくキュー投入であり、
   停止直前に受け取った出力は `reset()` の時点でほぼ常に未解析のまま残っている。`reset()` はその
   キューが今から描き込むバッファを空にするだけなので、直後に過去ログが描き戻る。よって `reset()` は
   2 回行う: 即座に 1 回（通常はこれで画面が消える）＋ `write('', cb)` の `cb`（自分より前にキューされた
   分の解析完了）でもう 1 回。フラグ 1 が新規投入を止めているので、この `cb` の後ろには何も積まれない。
   `cb` 内でフラグを再確認する（`start` 済み＝ユーザーが再起動したペインの初出力を消さないため）。

抑止するのは*表示*だけで、アーカイブ（JSONL/DB、main 側）は無関係。
再現条件は E2E に固定した（`fake-claude.js` の `#spew`）: 出力の少ないフェイクでは競合が運で app 側に
倒れるため、出力を流し続けるペインを停止して初めてこの欠陥が観測できる。

**D-4: 異議文は `evaluations.appeal_text` に持つ。移行は additive な `ALTER TABLE ... ADD COLUMN`。**
`CREATE TABLE IF NOT EXISTS` は既存テーブルに列を足さないので、`PRAGMA table_info` で列の有無を見て
無いときだけ `ADD COLUMN appeal_text TEXT` を実行する（TD-6 の冪等移行）。既存行は `NULL` のまま＝
「異議なしの評価」で意味が通る。append-only は不変（R-7）: 異議つき再評価も新しい行を作る。

**D-5: 異議文と直前評価はプロンプト本文に埋め込み、stdin だけで渡す。**
TD-5 / ADR-0010 D-2 と同じ injection 不変条件を継承する（argv には静的フラグしか載せない）。
プロンプトには「申し立てに無条件で迎合せず、抜粋の実データと突き合わせ、支持できない部分は判断を
維持してその旨を総評に書く」ことを明示する。異議申し立てを「点数を上げる依頼」にしないため。
異議文は 2000 文字で切り詰める（入力予算 `EVALUATION_INPUT_MAX_CHARS` を圧迫させない）。

## 影響

- `EvaluationSummary.appealText` / `EvaluationRerunRequest.appealText` が増える（IPC 契約の追加のみ）。
- `EvaluationCoordinator` に `getPreviousEvaluation` 依存が増える（異議時のみ呼ぶ）。
- 評価レポート（Markdown/JSON）に異議文の節が増える。
